## 1. Scope

M2-B implements the visual graph editor UI on top of the M2-A canonical graph model. It does not implement graph execution, persistence integration, or later milestones.

## 2. Implementation summary

### Dependency
- Added `@xyflow/react` `12.12.1` (presentation layer only; SimuForge owns the canonical graph).

### Adapter
- `app/src/graph/adapter.ts` converts canonical graph to React Flow nodes/edges, applies node position updates, and creates canonical nodes with per-type defaults.
- Editor-only metadata (selection, viewport, drag state) never enters the canonical graph.

### UI
- `app/src/ui/graph/GraphEditor.tsx` hosts the React Flow canvas, selection, drag/delete, connections, validation, diagnostics, and empty state.
- `app/src/ui/graph/GraphNodeRenderer.tsx` renders the six approved node types with input/output execution handles, configuration summary, selected state, and error state.
- `app/src/ui/graph/NodePalette.tsx` creates canonical nodes for the six approved types on a non-overlapping grid.
- `app/src/ui/graph/GraphNodeInspector.tsx` edits canonical node configuration.
- `app/src/ui/shell/StudioShell.tsx` hosts the palette and canvas in the Logic Editor (`Program`) panel.
- `app/src/ui/panels/Inspector.tsx` shows graph node configuration when a graph node is selected.
- `app/src/styles/shell.css` supplies the M2-B graph styling, including an inert React Flow node wrapper and dark canvas controls.

### State
- Added in-memory `graph` to `StudioState`.
- Added `selectedGraphNodeId` to `EditorState`.
- Added `graph/set` and `graph/select-node` commands.

### Edit translation
- Add node: canonical node with generated ID and grid position.
- Move node: position committed to the canonical graph on drag stop.
- Connect: canonical edge created only after canonical validation accepts it.
- Disconnect / delete: canonical edge or node removed; deleting a node also removes its edges and clears selection.
- Configuration edit: canonical node config updated, then revalidated.

## 4. Acceptance remediation (2026-11-12)

The first acceptance audit verified criteria 1, 2, 11, 12, and 13 but found criteria 3-10 NOT VERIFIED: the browser spec covered only a subset of behavior and the adapter had no unit tests. The following defects and evidence gaps were addressed in this pass.

### Defects fixed
- Removed debug `console.log` calls and a fallback "select" button that masked node-selection behavior.
- Restored canonical connection validation on connect, rejecting only diagnostics tied to the new edge or the graph-level cycle diagnostic so unrelated node-configuration errors cannot block a valid connection.
- Edge IDs now use `crypto.randomUUID()` so duplicate connections are detectable.
- Deleting a node now removes its connected edges and clears selection.
- Edge deletion now updates the canonical graph.
- Node drag commits position on drag stop instead of on every intermediate change; auto-pan during node drag is disabled so dragging no longer shifts the whole viewport.
- Pane drag is restricted to middle/right mouse, and `minZoom` is 0.2 so the short Program panel stays usable.
- Node selection stays transient editor state; the selected id is read from a ref and excluded from the rebuild effect, so selecting a node no longer rebuilds node identity mid-drag.
- Node wrapper styling is now inert (no white React Flow card), handles have a visible style plus a larger hit area, and the React Flow controls use the dark theme.
- New nodes are placed on a 280 x 180 grid so cards never overlap.
- Diagnostics render below the canvas instead of overlaying nodes.

### Evidence added
- `app/test/graph/adapter.test.ts` (7 tests): node/edge mapping, stable IDs, configuration survival, editor-only selection not serialized, position round-trip, serialization round-trip, six node defaults.
- `app/test/graph/graph.test.ts`: added endpoint/port validation, self-cycle rejection, node-specific target compatibility, and execution-kind port coverage.
- `app/tests/browser/m2b-graph-editor.spec.ts`: six focused scenarios with module-level evidence aggregation in `test.afterAll`, recording scenario status, viewport, assertions, screenshots, and browser version.
- Regenerated `reports/mvp-2/evidence/m2b-browser-acceptance.json` and all M2-B screenshots.

## 7. Known limitations

- Graph state is in-memory only; persistence is M2-E.
- No graph execution engine; M2-C and later are not implemented.
- Undo/redo is deferred.
- The Program panel is compact at short viewports; fit-to-view can zoom out to roughly 0.5 with two nodes at 1280 x 720. Nodes stay interactive and the 1440 x 900 layout is roomier.
- Node cards truncate the node ID with an ellipsis; the full ID is available in the card tooltip and in the Inspector.
- Diagnostics are not mirrored to the Console yet.
- Object-reference editing is a plain entity ID field; no picker yet.
